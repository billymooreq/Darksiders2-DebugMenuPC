# playerFly на PC — DLL v0.4 (задачи 04–05)

Код: `src/dbgmenu/flight.cpp` (логика, зависание, переход камеры), `game.cpp` (вызовы игры + подделка для теста), `hooks.cpp` (хуки), `input.cpp` (ввод, фокус), `cursor.cpp` (курсор), `menu.cpp` (пункты, строки FLY/HOVER). Механизм Xbox — `playerfly_xbox.md`, база PC — `camera_teleport_pc.md`.

## 1. Статика 04 [ПОДТВ статически, кроме помеченного]
- **Рендер берёт матрицу камеры так:** кадр 0x00B3D3E4 → … → `game->vt[0x50]()` (логика) → **0x00B3CD27** (ECX = game): `game->vt[0x7C](&m)` **0x004CD9DA** = копия **`(game+0x138)+0xC0`**; FOV = `game->vt[0x70]` 0x004CD9C4; `vt[0x78]/vt[0x74]` — near/far [ГИП]. vt[0x7C] зовут 8 мест (лог v0.3): 004D102D 00B3CD7E(рендер) 00B3B1C1 00B3BCB1 004CED0A 005D4801 00B3B860 00B3B86E — ~11 раз за кадр.
- Vtable игры **0x0116E230**: vt[0x68] 0x00B3C287 setPaused, vt[0x70] FOV, vt[0x7C] 0x004CD9DA getCameraMatrix.
- **StateCamera** (vt 0x01199EA0, ctor 0x005B664F/0x005B6A39): `+0x30` вектор смещения (ctor (0,0,1)), `+0x80` логическая матрица (строки: 0 right, 1 up, 2 back, 3 pos; dir = −строка 2); **`+0xC0` — для рендера**; `+0x100` вход update; `+0x15C` текущее состояние, `+0x160` дефолтное. vt[0x2C] 0x005B7640 setTarget (reset + новое дефолтное состояние), vt[0x34] 0x005B8599 tick (**в v0.3 ни разу не вызван** — счётчик tick=0), **vt[0x38] 0x005B5D33 update — вызывается раз в кадр и на паузе** (`state->vt[0x30](arg, cam+0x100)`), vt[0x58] — цель (игрок). setMatrix **0x005B5BEC** пишет `+0x80` и `+0xC0`.
- **setPaused 0x00B3C287**: работает только при `game+0x10 & 0x40`; счётчик `+0xF8` ≥ 0. **Игра сама** ставит свою паузу при потере фокуса (WM_ACTIVATEAPP 0 → 0x004037E5 → 0x004EA363(1)) и снимает при возврате (0x00403830) — в логе v0.3 «pause 2 -> 1».
- **Актёр игрока** (vt 0x01266568): getPos vt[0x38] 0x00885362 = `+0x260`; setPos vt[0x34] 0x00885681: если позиция изменилась — `+0x260 = pos`, vt[0x208], vt[0x204] 0x0077FA30 (если контроллер `+0x30C` стоит на земле и `+0x3B8 < 0` → `+0x3B8 = 0`); всегда `+0x230 = pos`; затем Actor::setPosition 0x0076A2F7. setYaw vt[0x138] 0x0077DE6A → vt[0x2C4] 0x007864B4(yaw, 0): `+0x140 = yaw` (градусы) и поворот; **getYaw vt[0x134] 0x008C3145 = `+0x140`**. dir→yaw 0x00ACB5FC.
- teleportTo 0x00796B71: `vt[0x34](&pos)` + `vt[0x138](yaw)`.

## 5. Статика 05 [ПОДТВ статически, кроме помеченного]
- **Курсор у игры:** `ClipCursor` вызывается только в 0x00403976 (WM_ACTIVATEAPP 0, `ClipCursor(NULL)`) — **игра курсор не запирает**; держит его в окне `SetCursorPos` в центр (0x0091BE79, если `GetFocus()==hwnd`), прячет/показывает циклами `ShowCursor` (0x00D4D087 / 0x00D4D07A, зовёт UI 0x005A1680), `GetCursorPos` 0x0091BEB2 — позиция для UI. На паузе это не работает → в v0.3 курсор был виден и уходил на второй монитор.
- **Камера за героем:** скриптовая `resetCamera` (строка 0x01171A4C, обработчик 0x004E572F) = `getCamera` + **StateCamera::reset 0x005B7348** (ECX = cam): цель `cam->vt[0x58]`, yaw цели `vt[0x134]` → матрица: поворот по Z на yaw, затем 90° (оси камеры), сдвиг `cam+0x30 × 195` назад, 10 лучей коллизии (притянуть камеру), `setMatrix 0x005B5BEC`. Наклон — ровный (горизонт). Игра сама делает **так же при переносе героя к объекту** (0x0088E5A0: setPos, setYaw, reset, затем **0x005D5B1A(cam, −1.0, −1.0)** — cdecl, переход в дефолтное состояние `cam+0x160`, создаёт его через 0x005D565A; = Xbox 0x825926E8). Почему v0.3 «отъезжала»: логическая камера все время полёта оставалась у старой позиции героя и после телепорта догоняла его своим ходом.
- **Вертикальная скорость игрока = `+0x3B8`** (float, < 0 — падение), `+0x3BC` — прошлое значение; рядом `+0x3C0`/`+0x3D0` — векторы (смысл не установлен). Доказательства: PlayerFall (строки 0x011E93D8/0x011E93E8, функции 0x006D75D0/0x006D7A08) проверяет `+0x3B8 < 0`, делит расстояние на `+0x3B8` (время до земли); функции get/set/clear 0x0077F46D/0x0077F4B5/0x0077F507 (clear зовут ~21 место); везде запись «prev = +0x3B8; +0x3B8 = new». Горизонтальная скорость — `+0x274` (getActualVelocity 0x0071367E = вектор из yaw и `+0x274`). **setPos скорость не сбрасывает** [ПОДТВ логом v0.3: телепорт в падении → после 1-го кадра −10.9, за 0.5 с −628]. Гравитация ≈ 1000 ед/с² (лог v0.3: −127 за 0.5 с из покоя) [ГИП-сильная]. Где интегрируется гравитация — не найдено (нет fadd/fsub с `[+0x3B8]`, значит через промежуточные переменные состояний).

## 2. Устройство v0.4
- **Раз в кадр** — хук **0x00B3D3E4** (`Flight_Frame()` до оригинального кадра): запросы F2/Enter/ЛКМ, пауза, телепорт, удержание (зависание), затем `Cursor_Update()`. Без хука — из Present (лог WARNING).
- **Свободная камера** — только бывшая «B»: хук **0x004CD9DA** (game vt[0x7C]) подменяет матрицу. Камера A (запись StateCamera, хуки tick/update) **удалена** (есть в git, тег review-04). Пункты меню fly camera / teleport method убраны.
- Матрица: yaw/pitch (|sin pitch| ≤ 0.95), строки `0 = sR·(fwd×Z)`, `1 = sU·(row0×fwd)`, `2 = −fwd`, `3 = pos`; знаки и w-столбец — из матрицы игры при входе. Знаки мыши/стрейфа подтверждены пользователем.
- **Курсор** (`cursor.cpp`): пока открыто меню или идёт полёт и окно в фокусе — счётчик `ShowCursor` < 0, `ClipCursor` в квадрат 4×4 px в центре клиентской области (каждый кадр проверяется). IAT-хуки `ShowCursor/ClipCursor/SetCursorPos` exe: пока захвачено — вызовы игры только запоминаются (виртуальный счётчик). При отпускании: счётчик = как его «видит» игра, clip = последний запрос игры (или найденный до нас), курсор — на место (только если фокус есть). При потере фокуса — отпускание сразу из WndProc (до обработчика игры). В тест-режиме системные функции подменены симуляцией.
- **Фокус** (`input.cpp`): WM_ACTIVATEAPP / WM_ACTIVATE / WM_KILLFOCUS / WM_SETFOCUS + `GetForegroundWindow`/`IsIconic`. Потеря → все удержания клавиш/кнопок и мышь сброшены. **Полёт не прерывается**: кадр без фокуса = «заморожен» (пауза остаётся, камера стоит, телепорт игнорируется), строка «FLY (paused, no focus)». Клик в первые 300 мс после возврата фокуса — не телепорт. **Reset устройства полёт не прерывает.**
- **Аварийный выход** (со снятием паузы) только: исключение в кадре полёта, пропал/сменился игрок, камера или объект игры (загрузка уровня), выгрузка DLL.
- **Телепорт**: `vt[0x34](&camPos)` + `vt[0x138](yaw свободной камеры)` + `+0x3B8 = +0x3BC = 0` (скорость падения не сохраняется) → снять паузу → **`reset 0x005B7348` + `0x005D5B1A(cam,−1,−1)`** (как игра в 0x0088E5A0) → **плавный переход 0.3 с**: в хуке vt[0x7C] матрица = slerp/lerp(свободная камера → матрица игры, smoothstep). Лог: камера до/после reset, середина перехода, конец, **«game camera 1 s after the teleport … yaw difference»**.
- **Зависание** (General → hover after teleport, по умолчанию on): игра идёт, перед каждым кадром — если позиция ушла: `vt[0x34](точка)`; `+0x3B8 = +0x3BC = 0` (только для vtable 0x01266568, иначе — только позиция + WARNING). Отпускание — первая **новая** нажатая клавиша/кнопка управления (кроме F-клавиш, Esc, Alt, Win, Tab, PrtSc, медиа; клавиши, зажатые в момент телепорта, игнорируются до отпускания; при открытом меню не считается): ставим точку и `vz = 0` в последний раз, нажатие уходит игре в тот же кадр. Снятие без отпускания: F2 (снова полёт), игрок/игра сменились, игра сама сдвинула героя > 40 ед (возрождение/удар/скрипт). Лог: `hover: START / RELEASED by <клавиша> (vz до/после, setPos, max drop/frame, max |vz| перед сбросом) / after release +0.1 s, +0.5 s (pos, vz)`, раз в 2 с — статистика.
- Строки: полёт — как в v0.3 (без «cam A/B»); без фокуса — `FLY (paused, no focus)`; зависание — `HOVER - press any move/jump key [F2 - fly again]` (в шрифте нет длинного тире).

## 4. Открытые вопросы (проверить в игре по логу v0.4)
- Держит ли обнуление `+0x3B8` падение (в логе `max |vz| before reset` должно быть ≈ g·dt ≈ 8–17, а не расти); после отпускания `+0.1 s vz` ≈ −100, `+0.5 s` ≈ −500. Если у состояния падения своя копия скорости — после отпускания будет рывок вниз (тогда искать её в PlayerFall).
- Смотрит ли камера после reset туда же (`yaw difference` в логе ≈ 0) и не уводит ли её дефолтное состояние; наклон после reset — горизонтальный (pitch свободной камеры не переносится).
- Доходит ли прыжок в воздухе (Space) как прыжок/двойной прыжок; не ломает ли зависание анимацию/состояния (долгое падение, смерть от падения).
- Курсор: виртуальный счётчик ShowCursor — если игра показывает курсор в своём меню паузы, после закрытия нашего меню он должен вернуться.
