# playerFly на PC — DLL v0.3 (задача 04)

Код: `src/dbgmenu/flight.cpp` (логика), `game.cpp` (вызовы игры + подделка для теста), `hooks.cpp` (хуки), `input.cpp` (ввод), `menu.cpp` (пункты, строка FLY). Механизм Xbox — `playerfly_xbox.md`, база PC — `camera_teleport_pc.md`.

## 1. Статика 04 [ПОДТВ статически, кроме помеченного]
- **Рендер берёт матрицу камеры так:** кадр 0x00B3D3E4 → … → `game->vt[0x50]()` (логика, в т.ч. тик камеры [ГИП]) → **0x00B3CD27** (ECX = game): `game->vt[0x7C](&m)` **0x004CD9DA** = копия **`(game+0x138)+0xC0`** (через 0x0067A03D = `lea eax,[ecx+0xC0]`); FOV = `game->vt[0x70]` 0x004CD9C4 → `cam->vt[0x4C]`; `vt[0x78]/vt[0x74]` — near/far [ГИП]. Т.е. рендер **не** берёт мир/узел сцены: `0x00B3B15C` = `game+0xBC → 0x00AC153E` возвращает **мир** (handle `+0xC` при `+0x10 == 4`), а не камеру.
- Vtable игры **0x0116E230** (Darksiders): vt[0x68] 0x00B3C287 setPaused, vt[0x70] FOV, vt[0x7C] 0x004CD9DA getCameraMatrix.
- **StateCamera** (vt 0x01199EA0, слоты до 0x5C, за ними строка «StateCamera»): `+0x80` логическая матрица (строки: 0 right, 1 up, 2 back, 3 pos; dir = −строка 2); **`+0xC0` — матрица для рендера**: тик **vt[0x34] 0x005B8599** (`ret 4`, arg — dt): состояние `+0x15C` → `0x004EB82F(cam+0x80, state, dt)`, копия `+0x80 → +0xC0`, затем эффекты на `+0xC0` (0x005B62D3, 0x005B7799, 0x005B7960, 0x005B825C — тряска и т.п. [ГИП]), запись `cam+0x80` в объект `+0x900` (слушатель звука? [ГИП]). setMatrix **0x005B5BEC** пишет `+0x80` и `+0xC0`. vt[0x38] 0x005B5D33 update(arg, Matrix*) (`ret 8`) — копирует вход в `+0x100`, зовёт `state->vt[0x30]`.
- **setPaused 0x00B3C287**: работает **только если `game+0x10 & 0x40`**; счётчик `+0xF8` = max(0, ±1) (снизу ограничен 0 → лишний false безвреден, но может снять чужую паузу); сообщает подсистеме `vt[100]`, `game+0x18`, миру (`0x004DB1CA`, `0x00A58D7F`).
- **Актёр игрока** (vt 0x01266568; лог v0.2): getPos vt[0x38] **0x00885362** = копия **`+0x260`**; setPos vt[0x34] **0x00885681**: если позиция изменилась — `+0x260 = pos`, `vt[0x208]` 0x00788FAF (→ 0x007870F5 с `+0x30C->vt[0x4C]` — смена «поверхности/региона» [ГИП]), `vt[0x204]` 0x0077FA30 (обнуляет `+0x3B8` при условии `+0x30C` — сброс скорости/падения [ГИП]); всегда `+0x230 = pos` (прошлая позиция — без «скорости» после переноса [ГИП]); если не стоят биты 11/12 `+0x1F0` → **Actor::setPosition 0x0076A2F7** (= Xbox 0x829AB738: `+0xF0`, узел сцены `+0xD4`, бит 9 `+0xA8`). Сырое `+0x90` у игрока = 0 — это нормально.
- setYaw vt[0x138] **0x0077DE6A** → `vt[0x2C4](yaw, 0)`. Yaw — **градусы [0,360)**; игровой dir→yaw **0x00ACB5FC** (`float __cdecl(const Vec*)`, только x,y; константы 90/270/360) — им пользуется teleportTo (0x00796EBE) и мы.
- teleportTo 0x00796B71: `vt[0x34](&pos)` (0x00796DB2), yaw = 0x00ACB5FC(&dir), `vt[0x138](yaw)`. Более надёжного пути (с отдельной синхронизацией физики) статически **не найдено** — setPos игрока уже сам обновляет всё, что видно.
- Кадр 0x00B3D3E4 вызывается только из 0x00B3D85F (Darksiders::run). Начинается с `while ([0x01531701]) Sleep(1000)` (неактивное окно? [ГИП]).

## 2. Устройство v0.3
- **Раз в кадр** — хук **0x00B3D3E4** (MinHook, проверка первых байт), `Flight_Frame()` **до** оригинального кадра: запросы (F2/Enter/ЛКМ/аварийные), пауза, телепорт — между кадрами; матрица готова до 0x00B3CD27. Present не подходит: он внутри кадра, после 0x00B3CD27 (камера опоздала бы на кадр) и посреди рендера (звать setPaused/setPos оттуда хуже). Если хук кадра не встал — запасной путь из Present (лог WARNING).
- **Камера A**: своя матрица в `StateCamera+0x80` и `+0xC0` — до кадра и после каждого тика vt[0x34] / update vt[0x38] (хуки 0x005B8599 / 0x005B5D33, только для `cam == game+0x138`). Вся игра видит свободную камеру.
- **Камера B** (по умолчанию): хук **0x004CD9DA** (game vt[0x7C]) — подменяет результат. Логическая камера продолжает смотреть на героя; меняется только картинка. В лог при выходе — список адресов возврата вызывающих vt[0x7C] (рендер = 0x00B3CD7E).
- Матрица: yaw/pitch (pitch: |sin| ≤ 0.95), строки `0 = sR·(fwd×Z)`, `1 = sU·(row0×fwd)`, `2 = −fwd`, `3 = pos`; знаки sR/sU и w-столбец берутся из игровой матрицы при входе (сохраняется «рукость» игры). Мышь вправо → поворот к строке 0 (считаем её «право экрана» [ГИП]).
- Скорость 375×2 ед/с × dt (QPC, dt ≤ 0.1 с), Shift ×3, Ctrl ×0.5, Space/C — по мировой Z.
- Ввод: удержание клавиш — своя таблица из WM_KEYDOWN/UP и Raw Input (`Input_KeyHeld`), мышь — raw `lLastX/lLastY` (в тесте — WM_MOUSEMOVE). Игре в полёте не доходит ничего (фильтр v0.2, `g_inputBlocked = меню || полёт`), пары нажатие/отпускание соблюдаются. Enter (WM_KEYDOWN) / ЛКМ (raw или WM_LBUTTONDOWN) — телепорт; при открытом меню полёт не управляется.
- Вход: game/camera/actor есть, pos героя ≠ 0, матрица конечная → `setPaused(true)`; если счётчик `+0xF8` не вырос — летим **без паузы** и `setPaused(false)` не зовём (баланс). Выход: ровно один `setPaused(false)`.
- Аварийный выход (со снятием паузы): исключение в кадре полёта, Reset устройства (флаг → следующий кадр), WM_ACTIVATEAPP(0), смена/потеря игрока или камеры, выгрузка DLL (при завершении процесса — только лог).
- Телепорт: `vt[0x34](&camPos)` + `vt[0x138](0x00ACB5FC(&fwd))`, затем выход с паузой. «teleport method»: `setPos` (один раз) / `setPos+repeat` (то же ещё на 3 первых кадрах после снятия паузы). Пробы позиции: после 1-го кадра, +0.5 с, +2 с (смещение от цели).
- Лог: `fly: ENTER/EXIT/TELEPORT/probe`, пауза до/после, game+0x10, строки матрицы, счётчики хуков (tick/update/A-writes/B-replaced), сумма движения мыши.

## 3. Офлайн-тест (`src/dbgmenu/test/test_d3d.cpp`, экспорт `DbgMenuTest(cmd)` — только в тест-режиме)
Подделка объектов игры в `game.cpp` (`Fake()`); команды: 1 уровень загружен, 2 игрок пропал, 3/4 камера пропала/вернулась, 5 исключение в кадре полёта. Сценарий: недоступно до загрузки → вход → W/мышь/Shift+D → Enter-телепорт → W доходит до игры; удержание A через выход (отпускание проглочено); Reset, WM_ACTIVATEAPP(0), исключение, потеря игрока → аварийный выход; меню в полёте (W не двигает), переключение камеры на A через меню, ЛКМ-телепорт. Пройден 2026-10-19: пауза везде 1→0, игре в полёте ничего не дошло.

## 4. Что проверить в игре (открытые вопросы)
- Берёт ли рендер на паузе камеру A и B (счётчики tick/update в логе покажут, тикает ли StateCamera на паузе).
- Не перевёрнуты ли мышь X и стрейф (строка 0 = право?).
- Работает ли пауза (`game+0x10` бит 0x40) и стоит ли мир.
- Остаётся ли герой в точке после снятия паузы (пробы), не «залипает» ли управление.
