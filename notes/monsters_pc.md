## 3. Устройство v0.10
- **Сбор** (с v0.10.2) — в кадре оверлея (Present = поток игры): миры (`Trig_Worlds`, как у триггеров) → **ActorManager** `0x004CF805(world)` → массив `+0x5C/+0x60` (элементы, `vt[0x1C]` → персонаж) и `+0x20/+0x24` (персонажи), без повторов. (v0.10–v0.10.1 брали EventManager `+0x8` — там только обработчики событий); на узел свой `__try`, длина ≤ count+64, указатель < 0x10000 — «плохой узел» без исключения. Класс — только если vt[4] — «чистый геттер» (`A1 xx xx xx xx C3` / `8B 81 disp32 C3` / `8B 41 disp8 C3`; иначе объект пропускается, лог раз на функцию), дескриптор с vt 0x0116228C; вид — по цепочке родителей (кэш по классу): Monster / NPC / Player. getPos вызывается только у 0x00885362 / 0x008EF6B2. Фильтр «show»: monsters / + NPC / all characters.
- **Поля** (только у показанных): имя = имя объекта (`+0x50`), если оно есть и отличается от класса, иначе имя класса (класс скрипта, напр. Skeleton_Archer); статы `+0x330`; макс. HP — getMaxHealth, но **только если `actor+0x410` уже есть** (тогда вызов только читает), иначе база `+0x8C` («(base max)»); строки из игры копируются с усечением (`_snprintf_s/_TRUNCATE`, не CRT-проверки, которые закрывают игру). Имена Name → кэш на 2048 имён (поиск у игры — один раз на имя).
- **Уровни (v0.10–v0.10.2; с v0.11 заменены папкой Display, §9)** (как Xbox, но имя и HP — всегда): строка 1 — имя (+ `[frozen]`), строка 2 — `HP cur/max lvl N`; L1 `move: <состояние>`; L2 + `AI: AIBehavior: <часть>` (монстры); L3 + `cooldowns: …`; L4 + `target: <имя> (N units, ~M m)`, `damage/defense/resistance`, `pos`. При damage info — `hit -N (t s ago) total -N in K` (4 с после удара).
- **Подписи (info: nearby)** — над верхом капсулы (`pos.z + высота + 8`, высоты нет → 150), проекция — матрицы кадра из хука 0x00983AFC (как у триггеров: в полёте и в переходе камеры тоже), за камерой/у near — не рисуется. Дальность — от камеры: 10/20/**30**/50/75/100/150 м/unlimited. Ближние первыми; подпись, налезающая на уже поставленную, поднимается над ней (до 3 раз), иначе пропускается; не больше 48. Фон — чёрный 45 %, текст белый (как Xbox), шрифт ×0.85; цель — жёлтая рамка.
- **Цель (info: target, F5)** — моб с наименьшим углом между направлением камеры и центром тела (`pos.z + высота/2`), ≤ 12°, без ограничения дальности, сквозь стены; текущая цель держится, пока ≤ 16° и не хуже лучшей на 3° (без мигания). Жёлтые уголки на центре тела; панель справа с 40 % высоты, ширина ≤ 38 % экрана (не закрывает центр; ниже панели showCameraPosition, в стороне от строк полёта/триггеров/надписи F10): имя, класс/объект/вид, HP и %, уровень/урон/защита/сопротивление, move, по уровню AI/кулдауны/цель, дистанция/угол/высота, позиция (L4), урон.
- **Сводка** (как Xbox-список) — внизу слева над строкой триггеров: `monsters [уровень] Monsters: N  labels a / b in 30 m  Characters (L4)  FROZEN  damage info`.
- **damage info** — пока пункт включён: `options+0x2F = 1` каждый кадр (если игра перечитала опции — снова 1); при выключении — значение игрока назад. Хуки **0x004DA98B / 0x004DA84D** (MinHook, проверка первых байт): на время вызова любой объект опций (и копия экрана настроек) показывает значение игрока → профиль не сохраняет наше, «опции изменились» из-за нас не бывает. Нет хуков → пункт отказывается. Свой подсчёт урона — по падению HP у показанных (таблица 256, запись в лог `monsters: hit …`).
- **freeze monsters** — проверка трёх мест кода (`80 3D 78 42 4D 01 00`) и значения 0/1, затем `0x014D4278 = 0`; назад — 1. Сам снимается: другой мир (`game+0xBC` → world) = загрузка, HP героя ≤ 0, F10 off, выгрузка DLL. Совместим с полётом/паузой/триггерами (флаги независимы).
- **F10 off** (`Mon_OnDebugOff`) — все 4 переключателя off, флаги назад сразу (WndProc = поток игры). Уровень/дальность/show не сбрасываются.
- **Лог**: `monsters: info ON …`; при включении — EventManager'ы, узлы, персонажи по видам, плохие узлы, классы с цепочкой родителей и числом, `field check` 4 первых (имя, класс, vt, позиция, статы, max (getMaxHealth/base), высота, move, AI, кулдауны, цель), высота капсулы героя; раз в 5 с — число, в дальности, подписей/пропущено, цель, время сбора/отрисовки; `target -> …`; `hit …`; `freeze ON/OFF (почему): flag 1 -> 0`; `damage info ON/OFF … (the game saved / compared the options N times)`; `vt[4] … not a plain getter`, `getPos … not a known one`; исключения (≤ 40) → функция off.

## 5. Открытые вопросы (по логу v0.10 в игре)
- Все ли мобы в списке актёров EventManager (`characters`/`monsters` в логе ≈ видимым), нет ли «not a plain getter» / «getPos not a known one» у нужных классов.
- Имена: класс скрипта и `+0x50` — читаемые ли; высота капсулы героя (`player proxy height`) — для сверки «1 м ≈ 32.8 ед.».
- `+0x18` = уровень, кулдауны (`+0x120`) и часть поведения (`+0xF8`→`+0xB0`) — правдоподобны ли значения.
- Появляются ли цифры урона игры (HUD `addDamageIndicator`) при damage info; не меняется ли сохранённая опция (лог: «saved / compared N times, it saw 0»).
- freeze: стоят ли мобы, не ломается ли анимация/смерть замороженных, нормально ли продолжают.

## 6. Проверка v0.10 в игре (2026-10-19) → v0.10.1
- Пользователь: **информация о монстрах не показывается** (мобы были прямо перед ним); **freeze monsters работает как надо**.
- Лог v0.10: `EventManagers 1, nodes 113, characters 0`; ни одного «odd getClass» → у объектов класс читался, но **дескриптор скриптового класса имеет vt 0x01166A08**, а v0.10 принимала только 0x0116228C. Исправлено: дескриптор признаётся по методам (vt[8] = 0x0054B0DD, vt[0x10] = 0x004898FD) — подходят оба. В лог при включении добавлено: сколько пропущено и почему (`no vtable / odd getClass / not a class descriptor / not a character / unknown getPos`), vtable отвергнутых дескрипторов, 24 первых класса «не персонажей» с цепочкой родителей; про героя — прокси `+0x190/+0x194/+0x198`, позиция, камера, HP.
- `player proxy height 20.0` → `+0x190` не рост; верх подписи теперь `+0x198`. Единица = 1 см (см. §2).
- «freeze OFF (the player died)» сразу после включения (23:35:05…33) — между ними герой ходил по триггерам у одной точки, а детекторы там пересоздавались (адреса 17FA4EE0 → 17F9C750 → 18000D00) = **возрождения**; т. е. герой, скорее всего, действительно умирал (меню игру не останавливает). v0.10.1: при HP ≤ 0 в момент включения — отказ «the player is dead»; снятие по смерти — только при переходе HP «> 0 → ≤ 0», значение HP пишется в лог.
- Опция DamageIndicators в профиле пользователя уже **1** (`DamageIndicators 1 -> 1`) — цифры урона игры, значит, включены и без меню.
- Выбор цели: оценка = угол + 1° на 10 м (раньше — только угол: дальний моб чуть ближе к центру отбирал цель у ближнего).
- Офлайн-тест v0.10.1: классы Skeleton/Ghoul подделки — со вторым vtable дескриптора; дальний скелет — 45 м; верх прокси `+0x198`; сценарий смерти — кадр 1737. Всё прошло.
