# playerFly на Xbox (DarksidersDebug.xex) — как устроено

Адреса — VA Xbox DEBUG (base 0x82000000). Источник: Ghidra (копия проекта Xbox в `_claudework/ghidra_xbox/`), декомпиляция в `dumps/decomp_xbox/{playerfly,flycam_state,flycam_input,inputmgr,actor_teleport}.c`, дизассемблер `scripts/ppcdis_xbox.py`.
Важно: адрес 0x825B3790 из `console_commands.md` — это **конструктор** объекта команды (init), а не обработчик. Обработчик — слот vtable.

## 1. Команда
- `0x825B3790` = ctor `PlayerFlyCommand`: базовый `ConsoleFunction(this, "playerFly", "Allow player to float…", cat 0)` → vtable **0x82052DE0**; `this+0x68` ← **0x46 = VK 'F'** (клавиша-ярлык команды; в Xenia F поэтому и работает) [ПОДТВ: константа 0x46 в ctor; что +0x68 — именно хоткей — ГИП, но совпадает с поведением]. Файл исходника: `DSConsoleCommandsGeneric.cpp`.
- vtable 0x82052DE0: +0 dtor 0x82A6BC10, **+8 execute = 0x825B42C8**, остальные — заглушки.

## 2. execute 0x825B42C8 (псевдокод) [ПОДТВ]
```c
S = *(Darksiders**)0x8376E9EC;         // синглтон игры Darksiders (gfc::OblivionGame), ленивая инициализация 0x82382D88
actor = 0x8242D9D0(&h, S);             // актёр игрока (handle, release 0x82380000)
cam   = 0x82749DE0(&h, S);             // = S+0x138 → камера-контроллер игрока (StateCamera)
if (actor && cam) {
    if (isFly(cam)) {                  // 0x825914A0: cam->state(+0x15C)->vt[0x40]() == 10
        cam->vt[0x44](&dir);           // направление взгляда
        actor->vt[0x13C](actor, yaw = 0x82EDDAB8(&dir));   // setYaw: yaw = atan2 в градусах, → vt[0x40] setRotation{0,0,yaw}
        actor->vt[0x38](actor, cam->vt[0x48](&pos));        // setPosition(позиция камеры)  ← ТЕЛЕПОРТ
    }
    0x82593790(cam, -1);               // переключить: войти в fly-состояние или выйти из него
    S->vt[0x68](S, isFly(cam));        // Game::setPaused(bool) 0x82A67B10: счётчик паузы +0xF8 → мир на паузе, персонаж стоит
    flags = 0x82A51828();              // глобальный объект флагов (тот же, что фильтр DebugRenderer, +0x40)
    flags->+0x3C: бит 0x200 и бит 0x100 = isFly   // [ГИП] скрыть HUD / режим отладочной камеры
}
```

## 3. Переключение состояния камеры 0x82593790(cam, ctl) [ПОДТВ]
- Камера: `cam+0x15C` — текущее состояние камеры (объект с vtable, `vt[0x40]` = тип), `cam+0x160` — состояние по умолчанию. Функции стека состояний: push/переход **0x82584908(f1=blendTime, f2=…, cam, &state)**, возврат к дефолтному **0x825926E8(f1=0.0, f2=-1.0, cam)**.
- Если сейчас тип 10 → `InputMgr+0x38 = -1`, `0x825926E8(cam)` (выход).
- Иначе → `InputMgr+0x38 = ctl` (если ≥0), `new FlyCameraState(0x68 байт, StateCameraUtil.cpp)` = **ctor 0x825BF0C0(mem, InputMgr+0x24)**, `0x82584908(f1=-1.0, f2=45.0, cam, &state)`.
- `InputMgr` = `[0x837827F4]` (ленивая инициализация 0x824319B0 → ctor 0x82491DB0, vtable 0x82024C90): +0x24 — индекс/контроллер, +0x36 bool «fly-камера активна», +0x38 активный контроллер, у него 24 логических кнопки (+0x4D, шаг 0xC) и 5 осей (+0x175).

## 4. FlyCameraState (тип 10), vtable **0x820554D0** [ПОДТВ, кроме помеченного]
База — CameraState ctor 0x82583278 (vtable 0x8204EA40): `+0x24` камера (объект с vt[0x44] dir, vt[0x48] pos, vt[0x50] FOV, vt[0x58]/vt[0x5C] — цель/актёр игрока, поле +0x4C = текущий FOV), `+0x2C` устройство ввода (из InputMgr, `0x824921E0`).
Свои поля: +0x54 handle устройства, +0x58 сохранённый FOV, +0x5C **флаг «выйти»**, +0x5D/+0x5E кнопка 0x19 сейчас/прошлый кадр, +0x5F/+0x60 кнопки 0x14/0x15 прошлого кадра, +0x64 handle замедления времени (-1 = нет).
| слот | функция | что делает |
|---|---|---|
| +0x40 | 0x823EDA70 | `return 10` — тип состояния |
| +0x6C | 0x825C0790 | onEnter: `InputMgr+0x36 = 1`, сохранить FOV (`cam->vt[0x50]`) в +0x58, сбросить флаги |
| +0x70 | **0x825BF7F8** | update (VMX, декомпиляция обрывается; разобран по ассемблеру `dumps/decomp_xbox/flycam_update.dis`) |
| +0x30 | 0x825C06E8 | если +0x5C: `0x824AE408(…,0)` (вернуть управление игроку: `S->vt[0x68](S,0)`), снять биты 0x200/0x100, `0x825926E8(cam)` → выход |
| +0x7C | 0x825BFC10 | onExit: `InputMgr+0x36 = 0`, вернуть FOV, снять замедление времени |

### Ввод 0x825BF1C8(state, &move, &rot) — вызывается из update [ПОДТВ]
- Устройство `dev` (`state+0x2C`): `dev->vt[0x20](dev, code, 0)` = кнопка нажата, `dev->vt[0x18](dev, axis, 0)` = ось.
- Коды — **логические** (таблица `base/GamepadControls` / `gamepad.gcon` в данных: ThumbLX/LY/RX/RY, LTrigger, RTrigger, ButtonA/X/Y/B, R/LShoulder, R/LThumb, Start, Back, DPad*). Какой физической кнопке соответствует код, статически не установлено [ГИП].
- Движение: оси 0,1 (левый стик), мёртвая зона 0.25, перемасштаб `(v∓0.25)·1.3333`; скорость `v · 375 · dt · 2.0` (константы 0x82055550 = 375.0, 0x82046AD4 = 2.0). Кнопка **0x18** держится → ×3.0, иначе **0x19** → ×0.5. Компоненты move: [0] вбок, [2] вперёд (по направлению взгляда, включая наклон — летит «куда смотрит»).
- Обзор: правый стик (через 0x82583380 → 0x82582538), те же мёртвая зона/кривая, инверсия X/Y по настройкам (0x825867B8 / 0x82586750), ограничение наклона: |forward·up| ≤ 0.95 (0x82055554/58).
- Кнопки **4 / 5**: FOV −/+ 10·dt, ограничение `[0.5·FOV0, 1.5·FOV0]`.
- Фронт нажатия кнопки 0x19 → вкл/выкл **замедление времени** (`0x82478878()->vt[0x44](-1.0, 0.75, 0.5, 0.5)`, снять `vt[0x4C]`) [ГИП: TimeManager/slow-mo].

### update 0x825BF7F8 — в конце кадра [ПОДТВ]
1. `0x825BF1C8` → move/rot; матрица камеры: поворот yaw/pitch (0x82539268 = rotation-matrix, 0x8242D208 = умножение 4×4), позиция += move в базисе камеры (`+0x30/+0x34/+0x38` матрицы).
2. **Кнопка 0x14 отпущена** (была нажата в прошлом кадре, `+0x5F`) → **телепорт**: `actor = cam->vt[0x5C]()`; `actor->vt[0x13C](yaw(cam->vt[0x44]))`; `actor->vt[0x38](cam->vt[0x48]())`; `+0x5C = 1` (выход).
3. Иначе **кнопка 0x15 отпущена** → `+0x5C = 1` (выход без телепорта — камера вернётся к игроку).
4. Запомнить состояния 0x14/0x15 в +0x5F/+0x60.
Выход фактически делает слот +0x30 на следующем кадре.

## 5. Телепорт = прямая запись позиции [ПОДТВ]
- `Actor::vt[0x38]` = **0x829AB738 setPosition(Vec3*)**: `actor+0xF0..0xF8 = pos`; если есть узел сцены `actor+0xD4` и не стоит бит 9 в `actor+0xA8` → `node+0x30..0x38 = pos`, `0x825C2080()` (обновить).
- `Actor::vt[0x13C]` = 0x82531290 setYaw(f1) → `vt[0x40](this, &{0,0,yaw})`.
- Точка = **ровно позиция камеры** (XYZ), луча вниз нет. «Примерно под камерой» — потому что персонаж затем падает под гравитацией [ГИП, со слов пользователя].
- Возврат управления: `S->vt[0x68](S, false)` = снять паузу (из execute или из 0x824AE408 при выходе по кнопке). Т.е. «персонаж стоит» потому, что **игра на паузе** (Game::setPaused, счётчик +0xF8), а камера-состояние продолжает обновляться [ГИП-сильная: 0x82A67B10 — счётчик +0xF8, при 0→1 сообщает подсистеме vt[0x60], объекту +0x18 и миру (0x82DDBD20); название «pause» — вывод].
- `Mover::Teleport` в этом пути **не участвует** (это, по строкам, NavPower-мувер ИИ: «TeleportToSpace called with AreaHandle…» [ГИП]).

## 7. Вывод для PC
Механизм простой: игра на паузу + своё состояние камеры + `setPosition` актёра. Для PC (где команды нет) можно не искать FlyCameraState, а сделать свою камеру: (1) поставить игру на паузу (PC: тот же `vt[0x68]` = 0x00B3C287 у объекта [0x0184E95C]), (2) переписывать матрицу вида/камеры каждый кадр, (3) по кнопке — `actor->setPosition(cam pos)` (аналог vt[0x38]) и вернуть управление. Нужны PC-аналоги: синглтон игрока, его vt[0x68], актёр vt[0x38], камера/матрица вида.
