# План реализации: дебаг-меню (playerFly + триггеры) для Darksiders II PC 2012

Состояние: план (задача 01). Ничего из этого в игре ещё не стоит. Адреса PC — см. `xbox_pc_map.md`.

## 0. Исходные факты (из разведки)
- exe x86, VC10, **без ASLR** (base 0x400000 всегда) → можно хукать по абсолютным адресам. Не упакован.
- Рендер: **D3D9** (`Direct3DCreate9` в импорте, D3DX9, только `Darksiders2.dsl` = DX9-шейдеры; DX11-код скомпилирован, но `Darksiders2.dx11sl` нет) [ГИП: проверит лог прокси — какие из d3d9/d3d11/dxgi загружены].
- Ввод: окно своё (RegisterClassExA/CreateWindowExA), **Raw Input** (`RegisterRawInputDevices`/`GetRawInputData`) — клавиатура/мышь, **XInput 1.3** (ординалы 2/3/4 = GetState/SetState/GetCapabilities) — геймпад, DirectInput8 — прочие джойстики, плюс `GetAsyncKeyState`.
- Дебаг-кода нет: консоль, команды, DebugRenderer, OblivionGameDebug вырезаны (строк нет; 0 из 206 описаний команд). Меню и отрисовку делаем сами.

## 1. Внедрение — прокси-DLL
| вариант | + | − |
|---|---|---|
| **dinput8.dll** (рекоменд.) | статический импорт exe (грузится на старте, до окна/устройства); не KnownDLL; 6 экспортов, игра зовёт один `DirectInput8Create`; стандарт для модов | DirectInput игре почти не нужен — но это и хорошо: прокси «прозрачен» |
| d3d9.dll | сразу ловим `Direct3DCreate9` → устройство | экспортов больше (D3DPERF_*, Direct3DCreate9Ex, Direct3DShaderValidatorCreate9…), конфликт с ReShade/другими d3d9-модами |
| xinput1_3.dll | удобно перехватить геймпад | импорт по ординалам, ловушка с DirectX-рантаймом; поздно для D3D-хуков нет, но менее привычно |
| winmm.dll / version.dll | — | winmm много экспортов; version.dll exe не импортирует — не загрузится |

Рекомендация: **dinput8.dll**, а D3D9 и XInput ловить изнутри через **патч IAT exe** (`Direct3DCreate9` @ IAT 0x01155730, `XInputGetState` ord#2 @ 0x011556D0) — IAT фиксирован без ASLR. Этап 6 (лог-прокси) проверяет сам факт загрузки.

## 2. Хуки
| что | как | зачем |
|---|---|---|
| `Direct3DCreate9` | IAT → обёртка возвращает реальный IDirect3D9, патчим его vtable `CreateDevice` (#16) | получить IDirect3DDevice9 |
| `IDirect3DDevice9::Present` (#17) / `EndScene` (#42) / `Reset` (#16) | vtable-патч (или MinHook на реализацию в d3d9.dll) | кадр оверлея; Reset — пересоздать ресурсы ImGui |
| WndProc | `SetWindowLongW(GWL_WNDPROC)` после создания окна (или хук `CreateWindowExA` / `RegisterClassExA` через IAT) | клавиатура для меню/полёта; глотать ввод, когда открыто меню |
| `GetRawInputData` | IAT-хук: обнулять данные, когда меню/полёт активны | игра читает клавиатуру/мышь через Raw Input |
| `XInputGetState` | IAT-хук: отдавать игре пустое состояние в меню/полёте, себе — настоящее | геймпад для меню и полёта |
| игровые функции (кадр, камера) | MinHook по абсолютным адресам | обновить камеру после игры и до рендера; найти игрока/мир |

**Хук-библиотека: MinHook** (BSD-2, x86 есть, ~10 файлов C, кладём исходники в `src/third_party/minhook`, собираем статически). Свой трамплин писать не стоит: нужен дизассемблер длины инструкций, MinHook это уже умеет (HDE32). IAT/vtable-патчи — свои 20 строк.

## 3. Отрисовка
| вариант | + | − |
|---|---|---|
| **Dear ImGui + backend DX9/Win32** (рекоменд. для меню) | готовые окна, шрифт, навигация с клавиатуры/геймпада, стилизуем «под Xbox» (тёмная полупрозрачная панель, категории, подсветка строки); MIT | +~1 МБ кода, нужно аккуратно с Reset |
| своё D3D9 (DrawPrimitiveUP + ID3DXFont) | минимально, полный контроль | меню и текст вручную |
| DebugRenderer игры | на Xbox так и сделано | **в PC его нет** (строк и классов не найдено) [ГИП: код удалён целиком] |

Для **3D-линий триггеров**: свой D3D9 `DrawPrimitiveUP(D3DPT_LINELIST)` с матрицами view/proj игровой камеры (z-test против сцены возможен, если рисуем до Present с её depth — проще без него, поверх) **или** проецировать вершины в 2D и рисовать линиями ImGui (`GetBackgroundDrawList`). Рекомендация: начать с ImGui-проекции (меньше состояний D3D), при необходимости — D3D-линии с глубиной. Матрица камеры — из игрового объекта камеры (PC-адрес найти; на Xbox — камера-контроллер `S+0x138`), запасной вариант — перехват `SetTransform`/`SetVertexShaderConstantF` (хрупко).

## 4. Меню «как на Xbox»
- Открыть/закрыть: клавиша (предлагаю **F1** или **`** ) и на геймпаде комбинация (например, Back+Start). Вверх/вниз — стрелки/D-pad, Enter/A — выполнить, Esc/B — назад.
- Структура: категории (General, Camera, Graphics…) → пункты; сначала только General → `playerFly`, Graphics → `Show triggers` (+ подпункты: радиус, фильтр TriggerRegion/все/выключенные, подписи).
- Пока меню открыто — игре не доходит ввод (см. хуки), пауза игры — по желанию (позже).

## 5. playerFly на PC
Xbox-механизм (`playerfly_xbox.md`): своё состояние камеры (тип 10) + **пауза игры** `Game::setPaused(true)` (`S->vt[0x68]`, на PC тот же слот = 0x00B3C287) + по кнопке `actor->vt[0x38] setPosition(позиция камеры)` и `vt[0x13C] setYaw`, затем `setPaused(false)`.
| вариант | + | − |
|---|---|---|
| A. Свободная камера своими силами (рекоменд.) | не зависим от вырезанного FlyCameraState; полный контроль скорости/клавиш | нужно найти, где игра берёт матрицу вида, и подменять её каждый кадр (хук камеры/рендера) |
| B. Восстановить игровое состояние камеры | ближе к оригиналу | класс FlyCameraState в retail, скорее всего, вырезан (строк камеры-отладки нет, кроме `@DebugCamera` [проверить]) |
Шаги A: (1) на вход — запомнить матрицу камеры, `setPaused(true)` (вопрос: продолжает ли PC-рендер обновлять вид камеры на паузе — проверить; иначе — заморозить только ввод игрока), (2) каждый кадр — WASD/мышь или стики двигают свою камеру (скорость 375 ед/с ×2, Shift ×3, Ctrl ×0.5 — как на Xbox), подменяем вид, (3) по клавише (например, **T** / кнопка A) — `setPosition` игрока в точку камеры (опция: луч вниз до пола — Havok raycast, позже), вернуть управление; по **F** без телепорта — просто вернуть камеру.

## 6. Триггеры на PC
Как на Xbox: от игрока `world = actor+0x58` → компонент EventManager мира → связный список детекторов (`evm+0x14`), фильтр по vtable, геометрия по `+0x80 Shape / +0x90 Pos / +0xA0 Rot / +0xB0 Scale / +0xD8 enabled`. Нужны PC-адреса getter-а EventManager и vtable детекторов (см. `xbox_pc_map.md`). Цвета как на Xbox.
