## 1. Статика 07 [ПОДТВ статически, кроме помеченного]
- **Миры.** Текущий мир один: `game+0xBC` — загрузчик мира (0x00B3B15C → 0x00AC153E): `+0x10 == 4` (готов) → мир `+0xC` (handle, refcount `+4`). Регионы подгружаются в этот же мир (как на Xbox). Обходим `actor+0x58` и текущий мир, одинаковые EventManager — один раз. Сколько миров в логе (`worlds=`) — проверка в игре.
- **EventManager** = `getEventManager 0x007735E8` (thiscall, ECX = world; map World+0x118, ключ `[0x015E7338]`, внутри addref/release). Два списка {head, tail, count}, узел 8 байт {next, obj} (добавление 0x00ABDBAD): `+0x8` — **обработчики событий** (VisScriptEventHandler / TriggerEventHandler / gamepad…; по логу v0.10.1 в игре — 116 штук, ни одного персонажа; персонажи — в ActorManager, `monsters_pc.md` §7) (0x00A40971 → 0x00ABDC71), **`+0x14` — детекторы** (DetectorObject::onAdd 0x008B84FE → 0x00ABDCC8; ещё один класс-актёр с телом-детектором — onAdd 0x0077AC87 → 0x0077AE88). Фильтр getRot/getScale (как на Xbox) отсекает не-SimpleShape.
- **Фигуры** (onAdd 0x008B84FE): 0 — AABB, полуразмеры `Scale × 0.5` ([0x013E70B0] = 0.5), поворот не используется; 1 — OBB `Scale/2`, трансформ **0x00A79856** (thiscall(obj, Matrix* out): identity → rotX → rotY → rotZ (каждый — умножение справа, градусы × [0x015352AC]) → translation +0x90; т.е. `M = Rx·Ry·Rz`, строки = оси; cos/sin — `_CIcos` 0x00DAE110 / `_CIsin` 0x00DAE116); 2 — сфера r = `Scale.z × 0.5`, только позиция (identity 0x01525F10); 3 — **настоящая капсула Havok** (0x00A96365 → 0x00E83400): отрезок (0,0,∓Scale.z/2) и радиус `Scale.x/2`, **без поворота** (только позиция). Xbox-патч рисует её ориентированным боксом (r, r, Scale.z/2) — v0.6 повторяет Xbox (просьба пользователя); полная высота настоящей капсулы = Scale.z + Scale.x.
- **Матрицы кадра.** 0x00B3CD27: `game->vt[0x7C]` (камера, сюда же попадает свободная камера/переход playerFly) → `[ebp-0x170]`; 0x00B3B1F2 = проекция **0x009055F7**(out, fov = vt[0x70]·[0x015352AC], aspect = (game+0x4C)->vt[0x2C](), zn = vt[0x74], zf = vt[0x78]) — **правосторонняя** перспектива: `m0 = ys/aspect, m5 = ys = cot(fov/2), m10 = −zf/(zf−zn), m11 = −1, m14 = −zn·zf/(zf−zn)`; затем **0x00983AFC**(thiscall renderView, camMat*, proj*, fov, aspect, zn, zf; `ret 0x18`): `+0x20` cam, `+0x60` view = 0x004EE2E3(cam) (обратная жёсткая), `+0xA0` proj, `+0xE0` view·proj, `+0x130..` 4 float. Вызовы 0x00983AFC: из 0x00B3CE2C (главная камера, адрес возврата **0x00B3CE31**), 0x00989F6F, 0x00ACB26A (другие — пропускаем). Вектор-строка (D3D): `clip = [p,1]·view·proj`, видно при `z ≥ 0`, `w = −vz`.
- **HUD-проход 0x00B3B8D2** (`__fastcall`, ECX = game; `ret`): viewport game+0x70, орто-проекция (0x00B3AB5B), `game->vt[0xC]` — UI. Вызовы: 0x00B3BC15 (обёртка, из кадра 0x00B3D629/0x00B3D69D), 0x00B3D494, 0x00B3D6C4. В кадре 0x00B3D3E4 он идёт после 0x00B3CD27 (камера), `renderer->vt[0x114]`, 0x00B3C0FB, 0x00B3B0DF (`(game+0x50)->vt[0x118]` — мир, или Clear) — т.е. после 3D-сцены [ГИП: рисует ли рендер синхронно — покажет timeline].
- Устройство: pp `D24S8 (75)`, без MSAA, 1920×1080 (лог v0.5).

## 2. Устройство v0.6
- **Сбор** — `Trig_Frame()` в хуке кадра 0x00B3D3E4 до оригинала (без хука — из Present): миры → EventManager → список `+0x14`; на узел — свой `__try` (битый объект пропускается, нечитаемый узел обрывает список), длина ≤ `count + 64` (≤ 65536), vtable — в образе exe, фильтр `vt[0x40] == 0x00A24AFB && vt[0x48] == 0x00A24B3D`. Снимок (до 32768): центр, полуразмеры, строки поворота, радиус, класс, shape, enabled. Исключение вне узла → триггеры **выключаются** (лог + статус).
- **Вид** — хук 0x00983AFC: при адресе возврата 0x00B3CE31 копия cam и proj, `vp = view·proj`, номер кадра. Рисуем только если вид из этого же кадра (загрузки/меню без 3D — ничего).
- **Отрисовка**: отсечение объектов по пирамиде (ближняя + 4 боковые плоскости из столбцов vp; дальней нет — без ограничения дальности); отрезки режутся в clip-пространстве (Liang–Barsky: `z ≥ 0`, `−w ≤ x,y ≤ w`) — у камеры и внутри триггера мусора нет. Боксы — 12 рёбер; сфера — 3 окружности (XY, XZ, YZ), 8…48 отрезков по экранному размеру (~10 px); фигура < 1.5 px — точка. Цвета как Xbox: TriggerRegion (vt 0x012702A0/0x012703F0) пурпурный, прочие голубые, выключенные серые (alpha 150, 1 px), включённые 2 px.
- **through walls** (по умолчанию): ImGui `GetBackgroundDrawList()` в оверлее (Present).
- **depth**: в начале HUD-прохода 0x00B3B8D2 — в текущую цель рендера с текущим depth (проверка: есть, размер ≥ цели, тот же MSAA), D3D9 `LINELIST` XYZRHW (z считаем сами из proj, сдвиг к камере `max(2, 0.3%·d)` против мерцания на полу/стенах, `ZFUNC LESSEQUAL`, без записи z, 2 px = вторая линия со сдвигом 1 px); state block D3DSBT_ALL. Не было HUD-прохода — то же в Present (back buffer). Нет годного depth → в этом кадре ImGui (статус «depth: n/a»). Своих D3D-ресурсов нет (DrawPrimitiveUP) → Reset ничего не требует.
- **Timeline**: при включении depth — один кадр всех `SetRenderTarget` / `SetDepthStencilSurface` / `Clear` (с адресом вызова и описанием поверхности) + отметки «render view», «HUD pass», «Present» → лог. Для поиска лучшей точки, если depth не закрывает линии.
- Меню **Triggers** (до v0.7 — Graphics, пункт `triggers depth`): `Show triggers [on/off] (shortcut F3)`, `depth < through walls / depth >`, `show disabled [on]`. Строка внизу слева (над строкой полёта): `triggers: N drawn / M total [режим]`.
- **Лог**: при включении — миры, EventManager, count/длина списка, найдено по классам (vtable) и shape, выключенных, ошибки; первый кадр — параметры вида (fov/aspect/near/far из proj, камера); точка depth (цель, depth, viewport) при каждом изменении; раз в 5 с (≤ 300 строк) — число, нарисовано, время сбора/отрисовки (среднее/макс), плохие вершины, другие вызовы 0x00983AFC; один раз — сверка нашего поворота с 0x00A79856 (`rotated shape check … same/DIFFERENT`).

## 6. v0.8 (задача 09): лог «trigger fired» и как детекторы ловят героя
Детектор = фантом Havok (тело `+0xD4`, vt 0x0126A020), «вход/выход» — колбэки перекрытия **0x008B82DD** (add, `ret 4`) / **0x008B815A** (remove, `ret 8`), общие для DetectorObject и TriggerRegion; событие игре — `detector->vt[0x130]/[0x134]` только если `+0xD8` (enabled). Подробно — `playerfly_pc.md` §7. Хуки (MinHook, проверка первых байт и слотов vt[0x14]/[0x18]) вызывают `Trig_OnDetectorAdd/Remove` **до** оригинала, только читают: объект с vt игрока 0x01266568, которого ещё нет в списке тела (add) / с последним коллайдером (remove) → строка `trigger fired: ENTER|EXIT …` (≤ 600 за запуск). Офлайн — `DbgMenuTest(15)` (подделка тела).

## 7. v0.12 (задача 13): информация о триггерах (как Monsters) + общая рефлексия
Код: `triggers.cpp` (раздел «task 13», подделка — `FakeInfoFields`, команды 29–31), `reflect.cpp` (рефлексия), `world.cpp` (карта, §8). Декомпиляция: `dumps/decomp_pc/trig13a..d.c`, `map13a..b.c`, Xbox `dumps/decomp_xbox/map13a..b.c`. Скрипт `scripts/proptypes.py` (тип / элемент / смещение по vtable свойства; `--types` — гистограмма); `propmap.py` теперь можно импортировать.

**Рефлексия игры** [ПОДТВ статически]:
- Дескриптор класса (vt 0x0116228C, скриптовый 0x01166A08): `+8` родитель, `+0x10` Name, **`+0x1C {data, count}` — свойства** (handles; addProperty 0x0048A740 → push_back 0x005757C4; ещё map `+0x34`). Свойство — статический объект (vtable на каждое свойство; напр. FilterList TriggerRegion = глобал 0x01587F68, vt 0x0126FE50): `+4` refcount, `+8` Name (имя), `+0x10` Name (описание).
- vtable свойства: **vt[1] (+4) тип** = константа (`6A n 58 C3`), **vt[4] (+0x10) тип элемента**, **vt[0xC] (+0x30) holder** `55 8B EC 51 83 65 FC 00 68 <getter>` (getter thiscall: `lea/mov/fld [ecx+d]`, `mov al,[ecx+d]`, биты `mov eax,[ecx+d]; shr; and al,1`, 64 бит `mov eax,[ecx+d]; mov edx,[ecx+d+4]`, виртуальный `mov eax,[ecx]; jmp [eax+slot]` → напр. Position = vt[0x38] 0x008EF6B2 «copy-out» `lea esi,[ecx+0x90]; movsd ×4`), **vt[0xD] (+0x34) count массива** `55 8B EC 8B 45 08 8B 80 <d> 5D C2 04 00` → `{data, count, cap}` с `d-4`, vt[0xE] (+0x38) reserve → размер элемента (`shl ecx, n`), vt[0x1A] (+0x68) copy, vt[0x1B] (+0x6C) init (имя). propmap.py брал copy — для Name / векторов / массивов там `off=?`.
- Типы: 0 ?, **2 int, 3 float, 4 bool, 5 std::string, 7 объект, 9 массив, 10 map, 11 struct из dword (вектор), 13 64 бит, 15 Name** (гистограмма по всем vtable свойств: `proptypes.py --types`).
- `reflect.cpp`: геттеры только разбираются по байтам (не вызываются), значение читается по смещению под `__try`; неизвестная форма → свойство «not read» + лог `reflect: property X ... not understood: <байты>` (≤ 80). Текст: Name → 0x00497245 (кэш 4096), массив — `[n] a, b, …` (≤ 12), struct — dword как int (|x| ≤ 100000), иначе float; vector4 из copy-out без w.

**TriggerRegion** (ctor 0x008C84E5, vt 0x012702A0; onAdd 0x008C8E47) [ПОДТВ статически]:

| смещение | поле (worlds.bin) | примечание |
|---|---|---|
| `+0xE0 / +0xEC / +0xF8 / +0x104 / +0x110` | FilterList / DefaultFilterList / NameFilter / OnEnterList / OnExitList — массивы Name (8 байт) `{data, count, cap}` | ctor кладёт «Player» в DefaultFilterList; onAdd: пустой FilterList ← DefaultFilterList |
| `+0x11C / +0x11D / +0x11E / +0x11F` | OneShot / Enable (по умолч. 1) / Exclude / RequireInWorld (по умолч. 1) | ctor пишет `0x01000100` |

- onEnter = vt[0x130] 0x008C77F9 → общий **0x008C8E8C**(actor, done*, list*, «onEnter»): `!Enable` → выход; OneShot и done → выход; RequireInWorld и `actor+0x58 == 0` → выход; **isActorTriggerable 0x008C8632** (фильтры); для каждого элемента списка «**Объект:Событие**» (без `:` — событие **Execute**, строка 0x0127052C): мир `+0x58` → поиск объекта по имени 0x00A46514 → отправка 0x004CEC21; затем **0x00676F02**(this, «onEnter», &actor): скриптовая функция с именем события (0x005645EF → 0x004BA3D9) и **слушатели объекта `+0x64`** (узел `{+0 ?, +4 слушатель, +8 next, +0xC выключен}`, счётчик-блокировка `+0x68`; 0x00A7DE70) → `done = 1`. onExit — то же с `+0x121`, `+0x110`.
- Связь «триггер → визуальный скрипт» только по имени (как в парсере worlds.bin): **TriggerEventModule** (vt 0x0129CC58): `+0x48` обработчик (TriggerEventHandler, vt 0x0129C910, EventHandler = WorldObject 0xC0 байт, `+0xB0` ?), `+0x50/+0x54` WorldObjects (Name), `+0x60` Name; 0x00A062A3 / 0x00A062F2 находят объекты по имени и цепляют / снимают обработчик (0x004C0331 / 0x00A7F547) → он виден в `+0x64` триггера [ГИП: что именно в узле — покажет лог].
- Другие классы (поля — рефлексией, смещение по геттеру): KillRegion Waypoint `+0x130` (0x00538F69), LoadRegion LoadOnEnter `+0xE0` (count `+0xE4`, элемент 8 байт = {id региона, слой; −1 = все}), UnloadOnEnter (count `+0xF0`), InteractiveRegion HUDText `+0x25C`, CameraInfluence MaxDistance и др. Скриптовые классы (killregiontrigger, setactivemaptrigger…) — дескриптор 0x01166A08, getClass `mov eax,[ecx+0x130]` (у TriggerRegion vt 0x012703F0) [ПОДТВ статически]; есть ли у них свойства скрипта (Region / Level / SpawnPoint) в списке `+0x1C` — по логу.
- Переход между мирами — модуль скрипта **WorldLoadModule** (WorldFile `+0x48`, Region `+0x50`, StartPoint `+0x58`; «To world '%s'» 0x008CEC2C) — он в скрипте, не на триггере; в v0.12 у триггера видно только слушателя (класс + имя).

**Устройство v0.12:** пункты Triggers: info: nearby / info: target (**F6**, KA_TRIGTARGET) / nearby range / папка Display (11 строк + all on / off, `g_trigShow[TF_*]`, по умолчанию name, class, leads to). Сбор идёт при Show triggers **или** info (без контуров тоже). В `Trig_Frame` сразу после сбора (объекты живы) — `InfoFrame`: точка отсчёта — герой (getPos), в свободном полёте — камера; дальность — до ближайшей точки объёма; ≤ 48 ближайших → `TInfo` (кэш 64 слота, полное чтение раз в 15 кадров, состояние — каждый кадр). Цель: луч из камеры (матрица кадра) — ближайший объём, в который он входит; камера внутри → самый маленький из окружающих; иначе ближайший к центру ≤ 8°; удержание, пока луч входит и лучший не ближе на 15 %. Рисование — только из текста: подписи у центра верхней грани (как Monsters: сдвиг вверх при наложении, ≤ 48), пустые строки в подписях не пишутся; цель — жёлтый контур + уголки; панель слева с 30 % высоты (при открытом меню — под ним, нет места — скрыта), «all properties» — сколько влезает, все — в лог при смене цели. Строка внизу слева: `triggers: N total [contours off] | labels a / b in 30 m | target: имя` (сводка Monsters поднимается над ней — `Trig_StatusShown`). F10 off → info off. Исключение в чтении / рисовании → info off + лог.
